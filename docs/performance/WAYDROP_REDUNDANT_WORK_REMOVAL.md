## Read ownership and security boundaries

Owners use current user and an in-memory credential identity, never logged/persisted. Original owners release only when both their visible result and all raw reads settle, and only if still the current map entry. A renewed-credential replacement can proceed while an older transport finishes; the old cleanup cannot erase the replacement. Separate deterministic Auth/profile tests pause an old owner, expire its visible deadline, renew credentials, claim a replacement, resume the old owner and join the replacement safely.

Existing three-second read phase deadlines, twelve-second load budget, completed transient-error backoff, schema-error quarantine, server Auth ban validation, deleted-profile checks, owner checks, profile projection and fresh privilege evaluation remain. There is no successful Auth/profile eligibility cache. Same-credential retries against a permanently hung transport remain failed until raw settlement; credential renewal permits independent validation. Transport cancellation is not claimed. `clear()` continues clearing schema quarantine without dropping raw request ownership.

Existing installed clients continue their old behavior until updated; this is not a server-wide suppression of all production writers.

The prior RiderAccessService and Storage request ownership/content-reconciliation corrections are preserved. Critical photo metadata INSERTs are **required to register a successful object** and are not disabled. Rider/KYC/users incident GETs are reads; stopping required account checks would not fix database writes and would weaken access control. Booking, atomic acceptance, payments, KYC, live GPS, availability and dispatch fallbacks are not disabled. No FCM-token suppression cache, timer/GPS rewrite, cron change or stale-worker deployment is introduced.
