### Remaining cleanup contract risks (inspection only)

`readKycReferences` awaits its query without an explicit deadline or abort signal. A rejected timeout is fail-closed, but a promise that never settles suspends the sequential folder scan indefinitely. The cron migration's `net.http_post` 30-second timeout bounds the caller's wait; it does not establish cancellation of Edge execution or its database request. A proposed future deadline must skip deletion on expiry and handle late completion safely; transport cancellation and runtime limits need verification before implementation.

The handler reads references, then awaits Storage removal separately. A successful empty lookup can be followed by a concurrent KYC commit referencing the selected objects before removal; claimed-folder pruning has the equivalent race for an object newly referenced after the lookup. Seven-day/one-hour age checks do not fence writers, and the upload service supports resumable generation paths and upsert uploads. Another reference read alone cannot close this check/use gap. Safe reclamation requires an approved protocol shared by reference writers and cleanup (claim/finalization fencing, immutable object identity, exhaustive reference inventory and retention rules), with isolated database/Storage concurrency tests. No such protocol, automatic deletion change, new deadline or backend contract was implemented in this readiness check.

Only this document changed during the readiness check. No runtime regression was measured, so no code fix, test rerun or analyzer run was justified. `git diff --check` is the required documentation validation.
